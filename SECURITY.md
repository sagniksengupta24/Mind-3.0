# Mind 3.0 Security & Trust Boundary Specification

This document provides an exhaustive, code-grounded analysis of data boundaries, network isolation, and sandbox enforcement in the Mind 3.0 VLSI design agent.

---

## 1. Threat Model & Core Invariants

Mind 3.0 is designed for autonomous and semi-autonomous register-transfer level (RTL) silicon synthesis and signoff. The threat model addresses three distinct risk surfaces:

1. **Proprietary Hardware Intellectual Property (IP) Exfiltration**: Unintended egress of natural-language functional specifications, pinout contracts, or proprietary SystemVerilog code to external multi-tenant cloud providers.
2. **Untrusted Code Execution & Lateral Host Movement**: Compromise of the local execution host via adversarial or hallucinated bash/python commands generated by LLMs during multi-turn repair loops.
3. **Trace Tampering & Fake Attestation**: Post-hoc manipulation of verification traces or claims of verification gates that never ran.

To mitigate these risks, Mind 3.0 implements four structural security invariants:
- **Host-Write / Sandbox-Exec Separation**: The LLM driver writes files on the host; all execution commands (compilation, formal verification, simulations) must run inside process isolation.
- **Strict Sandbox Fail-Closed Design**: If the sandbox binary is absent, unsandboxed execution is prohibited (`RuntimeError`).
- **Loopback-Only Verification**: Strict architectural partitioning between external cloud mode and local air-gapped/loopback-only mode.
- **Cryptographic Hash-Chained Telemetry**: Every state transition, action receipt, and verification outcome is bound by a sequential SHA-256 tamper-evident trace.

## 3. Cloud-Provider Mode (`provider="openrouter"`)

In cloud-provider mode, inference queries leave the local host and traverse public networks to OpenRouter's API endpoints.

### Code Paths
- **Endpoint Configuration**: Configured in [PhaseDriver.__init__](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L254-L262). Validates that `api_key` is provided directly or retrieved via `OPENROUTER_API_KEY` from the environment. Sets `self.base_url` to `https://openrouter.ai/api/v1`.
- **Dynamic Model Discovery**: [OpenRouterModelRegistry.fetch_models](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L102-L135) queries `https://openrouter.ai/api/v1/models` using an authenticated HTTP GET.
- **Inference Dispatch**: [PhaseDriver._query_openrouter](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L457-L516) sends an HTTP POST to `https://openrouter.ai/api/v1/chat/completions`.

### Exact Data Crossing the External Boundary
1. **HTTP Headers**:
   - `Authorization: Bearer <OPENROUTER_API_KEY>`
   - `Content-Type: application/json`
   - `HTTP-Referer: https://github.com/mind3/mind3`
   - `X-Title: Mind 3.0 VLSI Agent`
2. **Payload Content**:
   - `model`: Target model identifier (e.g. `openrouter/free`).
   - `messages`: Standard chat messages containing:
     - System prompt detailing hardware design rules, synthesis invariants (no latches, module-level variables), and role instructions.
     - Natural-language functional requirements.
     - Exact pinout declarations, signal bit-widths, and clock/reset definitions.
     - Generated formal SVA properties.
     - In repair turns: Exact diagnostic error reports emitted by synthesis tools (e.g., Yosys elaboration errors, latch detection traces, or SBY formal counterexample signals).

### Empirical Session Telemetry
During development and benchmarking sessions, real outbound network calls were executed against OpenRouter:
1. **API Reachability & Key Authorization Check**:
   - An HTTP GET was dispatched to `https://openrouter.ai/api/v1/auth/key` with the configured API key.
   - Returned status: HTTP 200 (Free Tier, 50 daily model request quota).
2. **Live Silicon Generation Trial (`fsm_01`)**:
   - An HTTP POST was dispatched to `https://openrouter.ai/api/v1/chat/completions` requesting contract synthesis and RTL implementation for a non-overlapping 1011 sequence detector.
   - Outbound payload included the module name `fsm_01`, expected ports (`clk`, `rst_n`, `data_in`, `match`), and target SVA assertion strings.
   - Received payload was a 34-line SystemVerilog module.

## 4. Loopback-Only / Air-Gapped Mode (`loopback_only=True`)

For high-assurance or proprietary silicon environments, Mind 3.0 provides strict loopback-only enforcement, aliased as `air_gapped=True`.

### Code Paths & Architectural Guarantees
- **Static Construction Interlock**: In [PhaseDriver.__init__](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L248-L252):
  ```python
  if self.loopback_only and self.provider == "openrouter":
      raise ValueError(
          "Loopback-only endpoint violation (air-gapped): external cloud provider 'openrouter' is forbidden when loopback_only=True. "
          "Use local inference engine ('ollama') with localhost/loopback address."
      )
  ```
- **Local Interface Enforcement**: In [PhaseDriver.__init__](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L266-L272):
  ```python
  if self.loopback_only:
      base_lower = self.base_url.lower()
      if not ("127.0.0.1" in base_lower or "localhost" in base_lower or "::1" in base_lower):
          raise ValueError(
              f"Loopback-only endpoint violation (air-gapped): endpoint '{self.base_url}' is not a local loopback interface. "
              "Loopback-only inference endpoint enforcement requires 127.0.0.1 or localhost."
          )
  ```
- **Data Boundary Guarantee**: Under `loopback_only=True`, inference traffic is dispatched exclusively via [PhaseDriver._query_ollama](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L441-L456) to local sockets on `127.0.0.1:11434`. No IP packets traverse physical network adapters.
- **Cryptographic Attestation Token**: Every trace event emitted under loopback mode computes and records a deterministic SHA-256 token ([driver.py:325-330](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L325-L330)):
  $$\text{SHA-256}(\text{session\_id} \mathbin{\Vert} \text{turn} \mathbin{\Vert} \text{step\_index} \mathbin{\Vert} \text{"LOOPBACK\_ONLY\_NO\_EGRESS"} \mathbin{\Vert} \text{prev\_hash})$$
  This token is stored as `loopback_attestation` (and `air_gapped_attestation`), providing a tamper-evident audit record that the run was configured without external egress.

## 5. Process Isolation & Network Sandboxing (`BubblewrapSandbox`)

Mind 3.0 executes all compiler, simulator, and verification tooling inside Linux Bubblewrap (`bwrap`).

### Code Implementation
Implemented in [src/mind3/sandbox/bwrap.py](file:///Users/sagniksengupta/Desktop/AI/src/mind3/sandbox/bwrap.py):
- **Invocation Arguments**:
  ```python
  cmd = [
      self._bwrap_bin,
      "--unshare-all",        # Unshares user, mount, IPC, PID, network, UTS namespaces
      "--die-with-parent",    # Kills sandbox processes if driver process terminates
      "--new-session",        # Allocates new session/process group
      "--proc", "/proc",
      "--dev", "/dev",
      "--tmpfs", "/tmp",
      "--ro-bind", "/usr", "/usr",
      "--ro-bind", "/bin", "/bin",
      "--ro-bind", "/lib", "/lib",
      "--bind", workspace, workspace,
      "--chdir", workspace,
      "--",
      *command
  ]
  ```
- **Network Isolation Mechanism**: The `--unshare-all` flag unshares the network namespace (`CLONE_NEWNET`). In this isolated namespace:
  - The loopback interface (`lo`) is created down/unconfigured.
  - No physical or virtual network interfaces from the host are inherited.
  - All outbound socket connections (`connect()`, `sendto()`) fail with `Network is unreachable` or `Connection refused`.
- **Automated Test**: [`test_bubblewrap_sandbox_network_isolation_outbound_blocked`](file:///Users/sagniksengupta/Desktop/AI/tests/test_mind3.py) tests outbound connection attempts to both public external addresses (`1.1.1.1:80`) and host loopback listeners, verifying that the sandbox blocks egress.
- **Host Platform Constraint**: Bubblewrap requires Linux kernel primitives (`clone()` with namespaces, `sys/capability.h`). On macOS (`Darwin`), `bwrap` is neither available nor buildable (`libcap: Linux is required`). `PhaseDriver` fails closed with:
  `RuntimeError: bwrap binary not found on PATH. Mind 3.0 forbids unsandboxed execution.`

## 6. Filesystem Security & Path Traversal Protections

To protect the host environment from path traversal attacks and accidental file destruction, [PhaseDriver._policy_check](file:///Users/sagniksengupta/Desktop/AI/src/mind3/core/driver.py#L540-L580) enforces deterministic validation on every agent action:

1. **Null Byte Injection**: Paths containing null bytes (`\x00`) are rejected with `ValueError`.
2. **Strict Canonical Resolution**: Target paths are resolved to absolute canonical paths. If `target_path` is not relative to `workspace.resolve()` (or `commonpath` deviates), `PermissionError` is raised.
3. **Root Overwrite Protection**: `target_path == workspace.resolve()` raises `PermissionError`.
4. **Internal State Protection**: Mutations targeting `.mind` internal metadata, snapshots, or `transcript.jsonl` raise `PermissionError`.
5. **Directory Collisions**: Attempting to write a file over an existing directory raises `IsADirectoryError`.

## 7. Credential & Environment Variable Handling

- **Storage**: `OPENROUTER_API_KEY` is loaded exclusively from environment variables or explicitly passed constructor arguments.
- **No Disk Logging**: API keys are never persisted to `.mind/transcript.jsonl`, benchmark transcript files (`benchmarks/transcripts/`), or git commit histories.
- **Git Tracking Exclusions**: Local credential storage files (`.env`, `.env.*`) must never be added to repository tracking.
